\textit{Steps 1--3 ordering.}
\texttt{xrfclk.set\_ref\_clks()} programs the LMK04828 and both
LMX2594 devices over \ac{spi} before \texttt{Overlay()} loads
the bitstream~\cite{xrfclk}.
Loading the bitstream first resets the \ac{rfdc} tile \acp{PLL}
and prevents lock acquisition; the 2\,s sleep in Step~2 covers
both \ac{PLL} stages, with on-board \acp{led} confirming lock
before execution continues.

\textit{Step 5: \texttt{FRAME\_SYNC\_CW} write.}
\texttt{FRAME\_SYNC\_CW} at PL-11 offset \texttt{0x20} is written and
readback-verified before the \ac{dma} channel is enabled.
A write during the active DATA phase of PL-06 propagates to the
in-flight frame trailer within one clock cycle
(Section~\ref{subsec:pl11}); boot-sequence ordering eliminates
this race.

\textit{Steps 6--7: tile check and \ac{nco} enforce.}
\texttt{TileState}~$< 15$ indicates a design indicates a design fault (misconfigured
overlay or clock failure) and halts execution with no runtime
recovery path.
Steps~1--3 must be verified before re-attempting.
The \ac{nco} enforce step reads back DAC~B Tile~228
\texttt{MixerSettings} and corrects the frequency to 177.0\,MHz
if the readback deviates by more than 0.001\,MHz.
The block design coarse mixer value ($F_s/4$, code~3) is overridden
to BYPASS (code~16) at this step. The block design default
never takes effect during operation (Section~\ref{subsec:dac_tile228}).

\subsection{DMA Control}
\label{subsec:ps_dma_control}

% ------------------------------------------------------------------
% §1  OVERVIEW
% ------------------------------------------------------------------

PS-03 is a \ac{pynq} notebook sequence executed on the \ac{arm}
Cortex-A53 \ac{ps}~\cite{PYNQ_DOC} that constructs a single
self-referencing \ac{sg} \ac{bd} in \ac{ddr} and kicks the
\ac{axi} \ac{dma} \ac{mm2s} channel (PL-01) into cyclic
operation~\cite{AMD_PG021}.
BD0 maps the full data buffer (\texttt{SOF=1}, \texttt{EOF=1})
with \texttt{NXTDESC} pointing to itself; the \ac{dma} engine
traverses this loop continuously.
All \ac{dma} register access uses raw \ac{mmio}~\cite{AMD_PG021}.

\FloatBarrier
\paragraph{DMA Kick Sequence.}

PS-03 validates \texttt{DATA\_LEN} for 188-byte alignment and the
\ac{sg} 26-bit transfer limit before allocating the \ac{bd} ring.
\texttt{bd\_mem} is allocated \texttt{cacheable=False}; uncached
allocation ensures the \ac{dma} engine sees up-to-date \ac{bd}
content without an explicit flush~\cite{AMD_PG021}.

The kick follows a register write order required by the \ac{axi}
\ac{dma} \ac{ip}: soft reset, \texttt{MM2S\_CURDESC} written
while halted, run with \texttt{CyclicBD=1} enabled, then
\texttt{MM2S\_TAILDESC} written to an out-of-chain address to
start descriptor fetches~\cite{AMD_PG021}.
In cyclic mode the engine ignores the \texttt{TAILDESC} pause
point and cycles the \ac{bd} ring continuously.

\texttt{mm2s\_introut} is unconnected; all status and error
monitoring is performed by polling
\texttt{MM2S\_DMASR}~\cite{AMD_PG021}.

% §6  INTERFACE CONTRACT

\FloatBarrier
\paragraph{Interface Contract.}

\textit{Upstream} ($\leftarrow$ PS-02 \texttt{j83b\_tx\_chain()}):
\begin{tightemize}
  \item \texttt{data\_buf.device\_address}: physical \ac{ddr} base
        address of the contiguous transmit buffer.
  \item \texttt{DATA\_LEN}: total byte count; multiple of~188;
        $\leq \texttt{0x3FFFFFF}$.
  \item \texttt{data\_buf.flush()} must have completed before
        PS-03 is called.
  \item \texttt{data\_buf} must remain allocated for the full
        duration of the \ac{dma} transfer; \texttt{freebuffer()}
        is called by PS-03 after \ac{dma} halt.
\end{tightemize}

\textit{Downstream} ($\rightarrow$ PL-01 \ac{axi} \ac{dma} \ac{mm2s}):
\begin{tightemize}
  \item PS-03 populates the \ac{bd} chain in \ac{ddr} and
        initiates transfer via the \texttt{MM2S\_TAILDESC}
        \ac{axi}-Lite write~\cite{AMD_PG021}.
  \item Both the \ac{sg} descriptor path (\texttt{M\_AXI\_SG})
        and the \ac{mm2s} data path (\texttt{M\_AXI\_MM2S})
        share \texttt{S\_AXI\_HPC0\_FPD} (SAXIGP0) via
        SmartConnect. No software isolation is required~\cite{AMD_PG247}.
  \item \ac{ddr} addresses are auto-assigned by Vivado and must
        be re-derived from \texttt{ip\_dict} or \texttt{.xsa}
        after every block design rebuild. Addresses must not
        be hardcoded.
  \item PL-02 asserts \texttt{tready=0} for one cycle at each
        \ac{mpegts} packet boundary (276{,}349 deassertions per
        cyclic pass). The \ac{dma} handles this via
        backpressure with no software action
        required~\cite{AMD_PG021}.
\end{tightemize}

\FloatBarrier
\paragraph{RTL Architecture.}
% [FIGURE OMITTED: datapath diagram figures/ch4_pl02_datapath — omitted by author]

Registered state consists of five elements: the 2-bit \ac{fsm} state,
an 8-bit byte counter (\texttt{byte\_cnt}), three 8-bit \ac{lfsr}
registers (\texttt{r1}, \texttt{r2}, \texttt{r3}), an 8-bit
\texttt{first7} capture register, and an 8-bit \texttt{checksum}
register.
Registers \texttt{r2} and \texttt{r3} are initialized to \texttt{0x00}
per the J.83B~\S\,B.4 specification and are never subsequently
updated~\cite{ITU_J83}. They are retained in the \ac{rtl} for
algorithmic traceability.

The \texttt{ph1\_lfsr\_chain} block implements the 8-step bit-serial
Phase~1 \ac{lfsr} computation as a fully unrolled \texttt{always\_comb}
loop, producing \texttt{r1\_ph1\_next} and \texttt{first7\_next} every
clock cycle.
Results are latched into \texttt{r1} and \texttt{first7} only on an
input handshake event while in \texttt{PH\_ONE}.
The \texttt{ph2\_lookup\_and\_drain} block executes unconditionally every
cycle, computing both the Phase~2 table-lookup result
(\texttt{r1\_ph2\_next}) and the full 8-step Phase~3 drain chain
(\texttt{checksum\_next}).
The drain result is latched into the \texttt{checksum} register only when
\texttt{byte\_cnt}~$\geq 187$ in \texttt{PH\_TWO}.
Running the drain chain unconditionally on every cycle simplifies control
logic at the cost of switching activity on the 186 non-drain cycles per
packet: a deferred power optimization with no functional impact.

\texttt{m\_axi\_tdata} is driven by a state-selected combinational mux:
it carries \texttt{checksum} in \texttt{PH\_THREE} and passes
\texttt{s\_axi\_tdata} through combinationally in all other states.
\texttt{s\_axi\_tready} is a priority conditional assignment that returns
\texttt{0} in \texttt{PH\_THREE}, \texttt{1} in \texttt{PH\_SYNC}, and
\texttt{m\_axi\_tready} otherwise.
Post-implementation timing analysis confirmed that the combinational
\texttt{s\_axi\_tready} path through \texttt{m\_axi\_tready} meets the
250\,MHz constraint with a worst negative slack of
$+2.687$\,ns~(Table~\ref{tab:pl02_timing}), so no registered pipeline
cut was introduced.

  \begin{minipage}{\linewidth}

    \texttt{out\_cnt}~$= 121$ (Horner stall; duration data-independent).

\texttt{s\_axi\_tready} is a pure combinational state decode
(\texttt{assign s\_axi\_tready = (state == ABSORB)}), with no path
from \texttt{m\_axi\_tready} to \texttt{s\_axi\_tready}.
Downstream backpressure from PL-04 does not propagate upstream to PL-02.

\FloatBarrier
\paragraph{RTL Architecture.}
% [FIGURE OMITTED: datapath diagram figures/ch4_pl03_datapath — omitted by author]

\textit{Bit masking.}
The J.83B \ac{rs} code operates on 7-bit $\mathrm{GF}(128)$ symbols.
The 8-bit \ac{axi}4-Stream bus carries one symbol per byte with bit~7
unused~\cite{ITU_J83}.
Bit~7 of \texttt{s\_axi\_tdata} is masked to zero before any
computation, and all output symbols are formed by the
\texttt{\{1'b0,\,cw[out\_cnt]\}} concatenation in the output mux,
hardwiring bit~7 to zero on every output byte.

\textit{\texttt{ABSORB}: \ac{lfsr} encoder.}
The five \texttt{gf\_mul\_rom} instances \texttt{gf\_rom1}--\texttt{gf\_rom5}
provide the $\mathrm{GF}(128)$ multiplications for generator coefficients
$G_1\!=\!62$, $G_2\!=\!46$, $G_3\!=\!98$, $G_4\!=\!70$,
$G_5\!=\!11$~\cite{ITU_J83}.
The feedback input to all five instances is gated combinationally to
zero outside \texttt{ABSORB}, suppressing spurious \ac{rom} switching
in emit states.
Each accepted symbol is simultaneously written into the 127-entry,
7-bit register array \texttt{cw[0:126]}.
On the final handshake at \texttt{sym\_cnt}~$= 121$, the five computed
parity values are snapshotted into \texttt{cw[122:126]}, completing
the 127-symbol codeword used by the Horner circuit.

\textit{\texttt{EMIT\_INFO}: Horner evaluator.}
The sixth instance \texttt{gf\_rom\_exp6} computes
$\bar{c} = c(\alpha^6)$ via Horner's method over \texttt{cw[0:126]}
while info bytes stream downstream.
Each step is one $\mathrm{GF}(128)$ multiply-accumulate:
$\mathtt{horner\_acc} \leftarrow
\mathrm{GF\_MUL}(\mathtt{horner\_acc},\,\alpha^6) \oplus
\mathtt{cw[horner\_cnt]}$.
After 126 steps the result is latched into \texttt{ext\_sym} and
\texttt{horner\_done} asserts, ending the 5-cycle output pause and
releasing the transition to \texttt{EMIT\_PAR}.

\textit{Register array and output mux.}
The \texttt{cw[0:126]} array of $127 \times 7 = 889$ flip-flops is the
dominant register resource.
Its combinational read is implemented by Vivado as a MUXF7/MUXF8
cascade, selecting \texttt{cw[out\_cnt]} for the output mux at the
full 250\,MHz clock rate.
The \texttt{parity[0:4]} registers and \texttt{cw[122:126]} hold
identical values after the parity snapshot but are not merged by
synthesis, adding redundant flip-flops to the \ac{ff} total reported
in Table~\ref{tab:pl03_resources}.

% §3  OPERATING PHASES

\FloatBarrier
\paragraph{Operating Phases.}

PL-04 uses a two-phase linear sequence controlled by \texttt{init\_done}
because the Ramsey Type~III algorithm requires all \ac{bram} delay
\acp{fifo} pre-initialised to zero; a fresh-reset \ac{bram} may contain
arbitrary data~\cite{ITU_J83}.

\textit{INIT phase (\texttt{!init\_done}) --- zero the delay lines.}
The zero-fill takes 8{,}128--8{,}132 clock cycles; upstream PL-03 must
not assume \texttt{s\_tready} is asserted at any fixed cycle after reset.

\textit{ACTIVE phase (\texttt{init\_done}) --- route bytes through branches.}
\texttt{branch\_cnt} cycles $0 \to 127 \to 0$ on every input handshake.
Branch~0 is a direct passthrough; each branch~$b$ from~1 to~127 reads
the byte that entered $b$~handshakes ago from a circular \ac{bram}
\ac{fifo} of depth~$b$ and writes the new byte to the same slot.
The single-bit \texttt{s0\_valid} flag is set on every input handshake
and held during downstream stalls, keeping \texttt{m\_axi\_tvalid}
asserted and the output stable.

Table~\ref{tab:pl04_phases} summarises the handshake signal values in
each phase.

  \label{tab:pl04_phases}

    \hline
    Phase  & \texttt{s\_axi\_tready} & \texttt{m\_axi\_tvalid} & Task \\
    \hline
    INIT   & \texttt{0}              & \texttt{0}
           & Zero-filling all 8{,}128 \ac{bram} delay slots before
             accepting any data (8{,}128--8{,}132 cycles) \\[4pt]

There is no elastic buffer between the \ac{bram} output and the
\ac{axi}4-Stream output; \texttt{s\_axi\_tready} tracks
\texttt{m\_axi\_tready} combinationally.
This is acceptable because PL-03 holds its output stable during all
emit phases and can tolerate an indefinite \texttt{s\_tready}
deassertion.

% ------------------------------------------------------------------
% §5  RTL ARCHITECTURE
% ------------------------------------------------------------------

\FloatBarrier
\paragraph{RTL Architecture.}
% [FIGURE OMITTED: datapath diagram figures/ch4_pl04_datapath — omitted by author]

\textit{Bit~7 preservation.}
Bit~7 is guaranteed zero by PL-03 and preserved without masking through
the \ac{bram} store-and-retrieve path.

\textit{INIT phase hardware.}
A 13-bit counter \texttt{init\_addr} increments every clock cycle while
\texttt{!init\_done}, driving both \texttt{addra} and \texttt{addrb}
simultaneously with \texttt{dina}~$= \texttt{0x00}$,
\texttt{ena}~$=$ \texttt{wea}~$= 1$.
When \texttt{init\_addr} reaches~8{,}127, \texttt{init\_done} is set by
a synchronous-set flip-flop (\texttt{FDSE}).

\textit{ACTIVE phase hardware --- branch addressing.}
For each branch~$b$, the flat \ac{bram} address is computed as
$\mathtt{base\_addr}(b) + \mathtt{wptr}[b]$, where
$\mathtt{base\_addr}(b) = b(b-1)/2$ is a pure combinational function
synthesized by Vivado as a CARRY8 adder tree,
and \texttt{wptr[b]} is the 7-bit circular pointer for branch~$b$,
ranging from~0 to~$b-1$ and wrapping at $b-1$.
The 128 write-pointer registers $\texttt{wptr[0:127]}$
($128 \times 7 = 896$ flip-flops) are the dominant register resource.
Their 128-to-1 selection into the address path is synthesized as a
MUXF7/MUXF8 cascade, which forms the critical timing path at 250\,MHz:
a setup path of approximately 5--7 logic levels from the
\texttt{wptr[]} registers through the CARRY8 adder and \ac{mux} tree
to the \ac{bram} address input.

\textit{ACTIVE phase hardware --- \ac{bram} access and output mux.}
For branches 1--127, both \texttt{ena} and \texttt{enb} are gated on
\texttt{input\_handshake}~\texttt{\&\&}~\texttt{(branch\_cnt}~$\neq$~\texttt{0)}.
Gating \texttt{enb} is a correctness requirement: without it, the
\ac{bram} would issue a spurious read during any downstream stall,
overwriting \texttt{dout\_bram} before the stalled output is
consumed~\cite{ARM_IHI0022}.
The output mux selects between these two paths combinationally:

\begin{equation}
  \mathtt{m\_axi\_tdata} =
  \begin{cases}
    \mathtt{s\_axi\_tdata\_d1} & \text{if } \mathtt{branch\_cnt\_d1} = 0 \\
    \mathtt{dout\_bram}        & \text{otherwise}
  \end{cases}
  \label{eq:interleaver_mux}
\end{equation}

\paragraph{Interface Contract.}

\textit{Upstream (\texttt{s\_axi\_*}, from PL-03 \ac{rs} encoder):}
\begin{tightemize}
  \item PL-03 delivers \ac{rs}-encoded bytes; interface contract details
        are defined at the PL-03 downstream boundary

  \item \texttt{s\_axi\_tready} is deasserted for 8{,}128--8{,}132 clock

        window; upstream must not assume \texttt{s\_tready} is asserted
        at any fixed cycle after reset.
  \item No \texttt{tlast} signal is used.
\end{tightemize}

\textit{Downstream (\texttt{m\_axi\_*}, to PL-05 randomizer):}
\begin{tightemize}
  \item Bit~7 is always zero.
  \item Output latency from input handshake to first valid output byte
        is exactly 1~clock cycle, equal to the \ac{bram} read latency.
  \item \texttt{m\_axi\_tdata} is combinational; downstream must sample
        on the rising clock edge coincident with
        \texttt{m\_axi\_tvalid}~\texttt{\&\&}~\texttt{m\_axi\_tready}.
  \item \texttt{m\_axi\_tdata} and \texttt{m\_axi\_tvalid} remain stable
        during downstream stalls~\cite{ARM_IHI0022}.
  \item No \texttt{tlast} signal is generated.
\end{tightemize}

\FloatBarrier
\paragraph{Streaming Operation.}

All output signals are combinational functions of the current inputs and
the \ac{pn} sequence counter \texttt{sym\_cnt}.
The core operation is a single bitwise XOR applied to every accepted
symbol:

\begin{equation}
  \mathtt{m\_axi\_tdata} =
  \left\{
    \texttt{1'b0},\;
    \mathtt{s\_axi\_tdata}[6:0] \oplus
    \mathtt{rseq\_rom}[\mathtt{sym\_cnt}]
  \right\}
  \label{eq:randomizer_xor}
\end{equation}

\noindent where \texttt{rseq\_rom[sym\_cnt]} is the precomputed
\ac{gf}(128) \ac{pn} sequence entry at the current symbol position.
Bit~7 of the output is hardwired to \texttt{1'b0}. All arithmetic
operates on the 7-bit symbol field.

The counter \texttt{sym\_cnt} advances by~1 on every input handshake,
cycling from~0 to~11{,}263 and wrapping to~0~\cite{ITU_J83}.
During downstream stalls or upstream valid gaps (such as the 5-cycle
Horner stall from PL-03), \texttt{sym\_cnt} freezes: no symbol is
accepted, no counter step occurs, and the \ac{pn} sequence position is
preserved exactly.

which apply uniformly at all times after reset.

\FloatBarrier
\paragraph{RTL Architecture.}
% [FIGURE OMITTED: datapath diagram figures/ch4_pl05_datapath — omitted by author]

\textit{\texttt{sym\_cnt} counter.}
The only registered element is the 14-bit counter \texttt{sym\_cnt[13:0]},
implemented as 14~logical flip-flops in the \ac{rtl}.
Because \texttt{sym\_cnt} addresses all 11{,}264 entries of
\texttt{RSEQ\_ROM}, each bit drives 1{,}358~\acp{lut}, producing a
high-fanout net on every counter bit.
Vivado automatically replicates \texttt{sym\_cnt} approximately 3.9 times
during implementation, yielding 54~\texttt{FDRE} primitives, to distribute
load across slices.
No \ac{rtl} change was required. The replication is a synthesis artifact.
The critical timing path at 250\,MHz is route-dominated:
\texttt{sym\_cnt\_reg\_rep[13]} $\to$ LUT3 $\to$ LUT6 $\to$ \ac{ff}
reset pin, with 89.1\% of the total data delay attributable to routing.

\textit{XOR datapath and output assignments.}
Bit~7 of the output is hardwired to \texttt{1'b0} via the
\texttt{\{1'b0, ...\}} concatenation, preserving the 7-bit symbol
constraint imposed by PL-03~\cite{ITU_J83}.
\texttt{s\_axi\_tready} and \texttt{m\_axi\_tvalid} are single
\texttt{assign} statements with no logic gates.

\textit{Combinational output boundary.}
\texttt{m\_axi\_tdata} is combinational: the output resolves in the same
cycle as input with zero pipeline latency.
This means the combinational path from PL-04's \ac{bram} output through
PL-05's XOR gate continues into PL-06's input, crossing two module
boundaries without a registered cut.
System-level functional correctness through the
PL-04$\to$PL-05$\to$PL-06 boundary was confirmed in integration
simulation and on board~\cite{PYNQ_DOC}.

\paragraph{Interface Contract.}

\textit{Upstream (\texttt{s\_axi\_*}, from PL-04 interleaver):}
\begin{tightemize}
  \item PL-04 delivers interleaved bytes; interface contract details are
        defined at the PL-04 downstream boundary
        (Section~\ref{subsec:pl04}).
  \item Unlike PL-04, there is no initialisation window. The module is
        ready to accept data the cycle after \texttt{rst\_n} is released.
  \item \texttt{sym\_cnt} freezes during PL-03 Horner stall gaps
        (\texttt{tvalid}~$= 0$, 5~cycles). No symbol is skipped or
        duplicated.
  \item No \texttt{tlast} signal is used.
\end{tightemize}

\textit{Downstream (\texttt{m\_axi\_*}, to PL-06 frame sync encoder):}
\begin{tightemize}
  \item Bit~7 is always zero.
  \item Output latency is zero: \texttt{m\_axi\_tdata} is valid in the
        same cycle as the input handshake. Downstream must sample on the
        rising clock edge when both \texttt{m\_axi\_tvalid} and
        \texttt{m\_axi\_tready} are asserted.
  \item \texttt{m\_axi\_tvalid} is a direct wire to
        \texttt{s\_axi\_tvalid}. During upstream valid gaps,
        \texttt{m\_axi\_tvalid}~$= 0$ and \texttt{m\_axi\_tdata} is
        undefined. Downstream must not sample during these periods.
  \item If upstream asserts \texttt{s\_axi\_tvalid}~$= 1$ while
        \texttt{rst\_n}~$= 0$, \texttt{m\_axi\_tvalid}~$= 1$ may assert.
        \texttt{sym\_cnt} does not advance during reset. Downstream
        PL-06 must gate sampling on \texttt{rst\_n}.
  \item No \texttt{tlast} signal is generated.
\end{tightemize}

The first input handshake from PL-05 latches the first symbol and transitions
the module from \texttt{IDLE} to \texttt{DATA}.

\texttt{s\_axi\_tready} asserts only at \texttt{bit\_cnt}~$= 6$, granting
PL-05 one transfer window every 7~clocks (1:7 upstream duty cycle).
When the last bit of the 11{,}264th symbol is serialized
(\texttt{sym\_cnt}~$= 11{,}264$, \texttt{bit\_cnt}~$= 6$),
\texttt{last\_sym\_last\_bit} triggers and the module transitions to
\texttt{TRAILER}.

\texttt{s\_axi\_tready} is hard-deasserted for the entire trailer window,
blocking upstream PL-05 for approximately 40~clock cycles.
The same 38-bit accumulator continues. Only the bit source changes from
\texttt{sym\_reg} to the combinational trailer \ac{lut} indexed by
\texttt{trailer\_cnt[5:0]}.
The 40~trailer bits complete group~2{,}074 (36 data bits already in the
accumulator are joined by the first 2 trailer bits) and fill group~2{,}075
(38 trailer bits exclusively).
When \texttt{trailer\_cnt}~$= 39$ and \texttt{grp\_done} fires,
group~2{,}075 is latched with \texttt{out\_tlast}~$= 1$, all counters reset,
and the module returns to \texttt{IDLE}.

\textit{Accumulator pipeline.}
The 38-bit shift register \texttt{accum[37:0]} accepts one bit per clock
when \texttt{accum\_en} asserts:
$\mathtt{accum} \leftarrow \{\mathtt{accum}[36:0],\,\mathtt{current\_bit}\}$.
A companion counter \texttt{accum\_cnt[5:0]} tracks the number of bits
written; when \texttt{accum\_cnt}~$= 37$ and \texttt{accum\_en} fire
simultaneously, \texttt{grp\_done} pulses.
On \texttt{grp\_done}, \texttt{out\_reg} latches the completed 38-bit group,
\texttt{accum} and \texttt{accum\_cnt} reset to zero, and \texttt{out\_valid}
is set.
This pipeline is shared between \texttt{DATA} and \texttt{TRAILER}. Only the
source of \texttt{current\_bit} changes between states.

\textit{Bit serializer.}
In \texttt{DATA}, \texttt{current\_bit} is driven by the bit serializer:
$\mathtt{data\_bit} = \mathtt{sym\_reg}[6 - \mathtt{bit\_cnt}]$, emitting
\texttt{sym\_reg[6]} (\ac{msb}) first.
The \texttt{bit\_cnt} counter advances when \texttt{bit\_shift\_en} asserts,
wrapping from~6 to~0 on each accepted symbol.
A correctness requirement governs this wrap: when \texttt{bit\_cnt}~$= 6$
and \texttt{s\_axi\_tvalid}~$= 0$, both \texttt{bit\_shift\_en} and
\texttt{accum\_en} are suppressed to hold the serializer and accumulator
frozen until a valid symbol arrives.
Without this suppression, a valid-low gap at \texttt{bit\_cnt}~$= 6$ would
wrap the counter and shift stale \texttt{sym\_reg} content into the
accumulator, misaligning \texttt{accum\_cnt} at the
\texttt{DATA}$\to$\texttt{TRAILER} boundary and making the terminal condition
of \texttt{TRAILER} unreachable.
For the final symbol (\texttt{sym\_cnt}~$= 11{,}264$), the suppression is
bypassed: once the 11{,}264th input handshake has occurred,
\texttt{s\_axi\_tready}~$= 0$ prevents any further upstream transfer and
\texttt{s\_axi\_tvalid} is irrelevant. The final symbol's 7-clock
serialization window must complete unconditionally.

\textit{Trailer source.}
In \texttt{TRAILER}, \texttt{current\_bit} is driven by a combinational
\ac{lut} indexed by \texttt{trailer\_cnt[5:0]}.
The 40~trailer bits are organized as four fixed sync bytes
(\texttt{0x71}, \texttt{0xE8}, \texttt{0x4D}, \texttt{0xD4}),
the 4-bit \texttt{ctrl\_word} at positions 32--35 (\ac{msb} first), and
four reserved zero bits at positions 36--39~\cite{ITU_J83}.
The fixed bytes are defined as localparams and constant-folded into
\ac{lut} logic by Vivado at synthesis. No \ac{rom} files, no \ac{bram},
and no \texttt{\$readmemh} are required.
\texttt{ctrl\_word} is read combinationally with no pipeline register.
A write to \texttt{FRAME\_SYNC\_CW} (PL-11, \ac{axi}4-Lite
offset~\texttt{0x20}) takes effect within the same clock cycle the write
completes.

\textit{Output register.}
\texttt{out\_reg}, \texttt{out\_valid}, and \texttt{out\_tlast} are all
registered on \texttt{grp\_done}, providing a registered cut between the
accumulator and the \ac{axi}4-Stream output.
\texttt{m\_axi\_tdata}~$=$ \texttt{\{2'b00, out\_reg\}}: bits~[39:38] are
permanently zero-padded to satisfy the \ac{axi}4-Stream requirement that
\texttt{TDATA} width be a multiple of~8 bits~\cite{ARM_IHI0022}. The
effective 38-bit trellis group occupies bits~[37:0].
\texttt{m\_axi\_tlast}~$=$ \texttt{out\_tlast \&\ out\_valid} ensures the
frame boundary signal can never assert without a valid transfer.

% §5  INTERFACE CONTRACT
% ------------------------------------------------------------------

\paragraph{Interface Contract.}

\textit{Upstream (\texttt{s\_axi\_*}, from PL-05 randomizer):}
\begin{tightemize}
  \item Input bytes carry 7-bit randomized symbols. Bit~7 is always zero
        and is truncated internally via
        \texttt{s\_tdata[6:0]}~\cite{ITU_J83}.
  \item \texttt{s\_axi\_tready} asserts for exactly one clock every
        7~cycles in \texttt{DATA}. PL-05 must hold \texttt{s\_axi\_tvalid}
        and \texttt{s\_axi\_tdata} stable during the 6~cycles when
        \texttt{s\_tready}~$= 0$~\cite{ARM_IHI0022}.
  \item Upstream valid gaps (including the 5-cycle Horner stall from
        PL-03) arriving at \texttt{bit\_cnt}~$= 6$ are handled by the
        serializer freeze: the bit counter and accumulator hold state
        until a valid symbol is present, with no data loss or
        \ac{pn} counter skip in PL-05.
  \item \texttt{s\_axi\_tready}~$= 0$ for the full \texttt{TRAILER} phase
        (approximately 40~clock cycles). PL-05 holds its output stable
        throughout.
  \item No \texttt{tlast} signal is used.
\end{tightemize}

\textit{Downstream (\texttt{m\_axi\_*} and \texttt{m\_axi\_tlast}, to
PL-07 trellis encoder):}
\begin{tightemize}
  \item Exactly 2{,}076 trellis groups are emitted per \ac{fec} frame,
        carried in \texttt{m\_axi\_tdata[37:0]}. Bits~[39:38] are
        permanently zero.
  \item \texttt{m\_axi\_tdata} is registered and remains stable while
        \texttt{m\_axi\_tvalid}~$= 1$ and
        \texttt{m\_axi\_tready}~$= 0$~\cite{ARM_IHI0022}.
  \item \texttt{m\_axi\_tlast} asserts on group~2{,}075 only, exactly once
        per \ac{fec} frame. PL-07 uses \texttt{tlast} to detect the frame
        boundary without a sideband group counter.
  \item \texttt{m\_axi\_tlast} is gated by \texttt{out\_valid} and can
        never assert without a simultaneous valid transfer.
\end{tightemize}

\textit{Parallel output design.}
All three ROMs resolve combinationally in a single pass; all five
C-words are assembled and registered into \texttt{out\_reg} in one
clock cycle.

\textit{tdata\_rev generate block — sync path only.}
PL-06 delivers groups \ac{msb}-first (\texttt{tdata[37]}~$=$~first
frame bit), but \texttt{sync\_buf} requires frame-order storage with
\texttt{sync\_buf[0]}~$=$~first bit.
A 38-way combinational generate block corrects this:
$\texttt{tdata\_rev}[i] = \texttt{s\_axi\_tdata}[37-i]$
for $i = 0 \ldots 37$.
The non-sync path reads \texttt{s\_axi\_tdata} directly and is
unaffected.

\FloatBarrier
\paragraph{Interface Contract.}

\textit{Upstream (\texttt{s\_axi\_*}, from PL-06):}
\begin{tightemize}
  \item Signal contract as defined in Section~\ref{subsec:pl06}.
  \item \texttt{s\_axi\_tready} asserts only in \texttt{IDLE} and
        \texttt{SYNC\_ACCUM}; PL-06 must hold \texttt{tdata} and
        \texttt{tvalid} stable during deassert~\cite{ARM_IHI0022}.
  \item \texttt{s\_axi\_tlast} must assert on group~2{,}075 only;
        \texttt{grp\_cnt} resets to zero on the same accepting cycle.
  \item Trellis state \texttt{XYp}/\texttt{Xq}/\texttt{Yq} freezes
        during any inter-frame \texttt{tvalid}~$= 0$ gap and is
        preserved for the first group of the next frame~\cite{ITU_J83}.
\end{tightemize}

\textit{Downstream (\texttt{m\_axi\_*}, to PL-08):}
\begin{tightemize}
  \item Delivers one 40-bit C-word bundle per input group, 1:1.
        \texttt{m\_tready}~$= 0$ propagates backpressure upstream to
        PL-06~\cite{ARM_IHI0022}.
  \item \texttt{m\_axi\_tvalid} is registered; a 1-cycle valid gap
        occurs between consecutive \texttt{SYNC\_EMIT} outputs while
        \texttt{out\_reg} reloads.
        PL-08 must tolerate non-consecutive valid assertion.
  \item \texttt{m\_axi\_tlast} asserts on the 5th \texttt{SYNC\_EMIT}
        bundle of each frame only.
\end{tightemize}

Three correctness requirements govern the RTL implementation of this
datapath.

\textit{Input latch (\texttt{tdata\_lat\_r}/\texttt{tlast\_lat\_r}).}
The \ac{rom} read addresses \texttt{tdata\_lat\_r} rather than the
live \texttt{s\_axi\_tdata} port.
The live port is not stable for the full five-cycle drain: upstream
PL-07 may deassert \texttt{s\_axi\_tdata} after the input handshake,
and on the \texttt{drain\_continue} path a new bundle's data arrives
the same cycle \texttt{sym[4]} is still being addressed.
Latching both \texttt{tdata} and \texttt{tlast} at \texttt{load\_en}
freezes the bundle for the entire drain window and eliminates the race.

\textit{Output hold register (\texttt{out\_valid\_r}).}
\texttt{out\_valid\_r} is a hold register: set on \texttt{output\_en}
and cleared only on \texttt{output\_handshake}, never on a state
transition.
Without this, any downstream stall cycle in which
\texttt{m\_tready}~$= 0$ would clear \texttt{out\_valid\_r} and
re-assert \texttt{drain\_en} through the \texttt{!out\_valid\_r} path,
advancing \texttt{drain\_cnt\_r} into the wrong symbol and oscillating
\texttt{m\_axi\_tvalid} on every stall cycle.
The hold-register pattern satisfies the \ac{axi}4-Stream data-stability
requirement~\cite{ARM_IHI0022}.

\textit{\texttt{m\_axi\_tlast} valid gate.}
\texttt{m\_axi\_tlast} is driven as
\texttt{out\_valid\_r \&\& out\_tlast\_r} rather than from
\texttt{out\_tlast\_r} alone.
\texttt{out\_tlast\_r} is updated only on \texttt{output\_en} cycles;
after the \texttt{DRAIN}$\to$\texttt{IDLE} transition,
\texttt{output\_en}~$= 0$ and \texttt{out\_tlast\_r} retains its last
captured value.
Without the valid gate, a stale \texttt{out\_tlast\_r}~$= 1$ would
propagate to \texttt{m\_axi\_tlast} at inter-frame boundaries while
\texttt{m\_axi\_tvalid}~$= 0$, violating the \ac{axi}4-Stream
protocol~\cite{ARM_IHI0022}.

\textit{\texttt{s\_axi\_tready} drain gate.}
\texttt{s\_axi\_tready} in \texttt{DRAIN} asserts only when
\texttt{output\_en \&\& last\_symbol\_done}: the exact cycle
\texttt{sym[4]} is captured into \texttt{iq\_out\_r}, not on
\texttt{drain\_cnt\_r}~$= 4$ alone.
Under downstream backpressure, \texttt{drain\_cnt\_r} can reach~4
several cycles before \texttt{output\_en} fires; using
\texttt{drain\_cnt\_r}~$= 4$ alone as the gate would admit the next
bundle and overwrite \texttt{tdata\_lat\_r} before \texttt{sym[4]} was

\end{tightemize}

\begin{tightemize}

        Section~\ref{subsec:pl09}.

        and \texttt{sym[0]} of the next.

Table~\ref{tab:pl09_config} lists the full \ac{fir} Compiler configuration.
Three hardware design decisions shaped these parameters.

\textit{Fix51\_49 input format.}
The \ac{fir} Compiler's input width ceiling is 51~bits when the
coefficient width is set to 35~bits or fewer (Table~\ref{tab:pl09_config}).
The input format was data-driven from the governing maximum
amplitude of all 256 constellation points:
$\max|\text{IQ}| = 1.150447483271056$
(deterministic, independent of packet count~\cite{ITU_J83}).
Applying $\lceil\log_2(\max|\text{IQ}|)\rceil + 1 = 2$ integer bits and
$51 - 2 = 49$ fractional bits fills the available \ac{ip} input ceiling
with no unused precision; a naive formula ($\lceil\log_2(\max+1)\rceil + 1$)
over-inflates the integer field by one bit when \texttt{max} lies just
above a power-of-two boundary, wasting one fractional bit.
Table~\ref{tab:pl09_fix51} defines the resulting Fix51\_49 format and
constitutes the authoritative contract for the upstream constellation
mapper (PL-08, Section~\ref{subsec:pl08}).

\textit{Integer Coefficients mode.}
The \ac{ip} restricts fractional coefficient bits to at most~3 for
coefficient widths in the 33--35~bit range~\cite{AMD_PG149}.
The \ac{srrc} center tap $\max|h| = 0.422$ requires approximately
34~fractional bits to represent faithfully; Fix35\_3 gives an \ac{lsb}
of $2^{-3} = 0.125$, which rounds the center tap to 0.375 or 0.5
and invalidates the passband response.
Integer Coefficients mode was therefore selected: the coefficients are
pre-scaled to Fix35\_0 integers in MATLAB before loading into the \ac{ip}
via the coefficient file (Table~\ref{tab:pl09_coeff}).

\paragraph{Interface Contract.}

\textit{Upstream} ($\leftarrow$ PL-08 \texttt{QAM256\_MAP}
via the format packer):
\begin{tightemize}
  \item PL-08 delivers Fix51\_49 \ac{iq} samples on a 128-bit
        \ac{axi}-Stream bus.
        The format packer remaps the word to the 112-bit \ac{fir} \ac{ip}
        input format (Figure~\ref{fig:pl09_packer}), adding one cycle of
        pipeline latency.
        \texttt{tready} is a combinational passthrough from the \ac{ip}.
  \item The \ac{ip} sees Fix51\_49 signed integers at
        \texttt{s\_tdata[50:0]} (\texttt{PATH\_0}~$=$~I) and
        \texttt{s\_tdata[106:56]} (\texttt{PATH\_1}~$=$~Q) with no
        external scale factor.
        $\max|\text{IQ}|$ is bounded by the \ac{qam256}
        constellation table (Section~\ref{subsec:pl08}).
  \item \texttt{s\_tready} deasserts between inputs (Systolic \ac{mac}
        is rate-limited at $250 / 5.361$\,MHz~$\approx 46.6$ cycles per
        input).
        Upstream must hold \texttt{tdata} and \texttt{tvalid} stable
        while \texttt{s\_tready}~$= 0$.
  \item \texttt{S\_DATA\_HAS\_FIFO = true}: the \ac{ip}'s internal input
        \ac{fifo} buffers transactions and reduces upstream stall sensitivity.
\end{tightemize}

\textit{Downstream} ($\rightarrow$ \ac{rfdc}-01 \ac{dac} Tile~228
via \ac{cdc} \ac{fifo}):
\begin{tightemize}
  \item Delivers Fix16\_0 signed 16-bit \ac{iq} samples on a 32-bit
        \ac{axi}-Stream bus: I in \texttt{tdata[15:0]},
        Q in \texttt{tdata[31:16]}.
  \item \ac{crte} truncation Fix87\_49~$\to$~Fix16\_0 is performed
        entirely inside the \ac{ip}.
        No external quantization block is required~\cite{AMD_PG149}.
  \item Output rate: $5.360\,537 \times 6 = 32.163$\,MSamp/s.
        \texttt{m\_tvalid} is asserted continuously once the pipeline
        fills after the 25-cycle startup.
  \item Downstream (\ac{cdc} \ac{fifo}) must assert \texttt{m\_tready}
        continuously.
  \item The \texttt{tlast} port is present for \ac{dma} loopback framing;
        in the production chain PL-09~$\to$~\ac{rfdc}-01, neither the
        \ac{fir} computation nor the \ac{rfdc} \ac{dac} tile depends on
        \texttt{tlast}.
\end{tightemize}

\paragraph{RTL Architecture.}

\texttt{anspect\_ctrl\_regs} consists of a thin top-level wrapper
that instantiates the Vivado \ac{ip} Packager-generated \ac{axi}-Lite slave,
customized with application-specific register names, bit-width
constraints, and combinational output port assignments.
Nine register slots are mapped across a 6-bit address space
(\texttt{C\_S\_AXI\_ADDR\_WIDTH}~=~6); address bits [5:2] form a
4-bit decode index giving sixteen addressable slots, of which nine
are used (Table~\ref{tab:regmap_pl11}).
All five configuration output ports are combinational assigns directly
from \texttt{slv\_regN[K:0]}.
No pipeline register is interposed between the register file and the
downstream consumer.
Registers \texttt{slv\_reg5}, \texttt{slv\_reg6}, and
\texttt{slv\_reg7} are declared but their write-path case arms are
disabled for future use.
Synthesis eliminates the dead flip-flops.

\paragraph{Interface Contract.}

\textit{Upstream} ($\leftarrow$ \ac{ps} via \texttt{axi\_smc\_ctrl}):
\begin{tightemize}
  \item The \ac{ps} reaches \texttt{S00\_AXI} through
        \texttt{axi\_smc\_ctrl} M00\_AXI. No direct \ac{ps} \ac{mmio}
        connection exists in the block design.
  \item All register writes must complete before the \ac{ps} enables the
        \ac{axi} \ac{dma} MM2S channel.
        Write ordering is the responsibility of PS-02
        (\texttt{j83b\_tx\_chain}).
  \item Output ports update combinationally within one clock cycle of
        the \ac{axi}-Lite write transaction completing.
\end{tightemize}

\textit{Downstream} ($\rightarrow$ PL-06 \texttt{FRAME\_SYNC\_ENC}):
\begin{tightemize}
  \item \texttt{frame\_sync\_cw[3:0]} is the only output port
        connected in the current block design. It drives PL-06
        \texttt{ctrl\_word}, supplying the upper nibble of trailer
        byte~4.
  \item PL-06 samples \texttt{frame\_sync\_cw} combinationally in
        its \textsc{Trailer} state.
        A write to offset \texttt{0x20} during an active data phase
        propagates to the in-flight frame within one clock cycle.
        The boot sequence must write \texttt{FRAME\_SYNC\_CW} before
        TX chain enable to avoid a mid-frame update.
  \item \texttt{ctrl\_out}, \texttt{mode\_out}, \texttt{alpha\_out},
        and \texttt{ldpc\_rate\_out} are unconnected in the current
        block design.
        Stub registers at offsets \texttt{0x10}–\texttt{0x1C} return
        \texttt{32'h0}.
\end{tightemize}

The \texttt{s0\_axis\_aclk} domain (32.1632\,MHz) is derived from
\texttt{clk\_dac0} via a Vivado Clock Wizard \ac{ip} instance
configured to divide 40.204\,MHz to 32.1632\,MHz, ensuring the
\ac{axi}4-Stream fabric clock is synchronous with the \ac{rfdac}
tile clock network~\cite{AMD_PG269}.
The \ac{axi}4-Lite configuration domain (\texttt{s\_axi\_aclk},
100\,MHz) and the \ac{axi}4-Stream data domain
(\texttt{s0\_axis\_aclk}, 32.1632\,MHz) are asynchronous.
\ac{cdc} between them is handled by a synchronizer chain generated
automatically by the \ac{rfdc} \ac{ip} wrapper~\cite{AMD_PG269}.
The \texttt{clk\_dac0} output (40.204\,MHz) is driven from the
\ac{rfdac} tile clock network via a \texttt{BUFG\_GT} primitive
and is exported to the \ac{pl} fabric as the master clock for the
upstream \ac{cdc} \ac{fifo}~\cite{AMD_PG269}.

\paragraph{Interface Contract.}

\textit{Upstream} (\texttt{s00\_axis\_*}, from \ac{cdc} \ac{fifo}):
\begin{tightemize}
  \item \texttt{s00\_axis\_tdata[31:0]} carries one complex
        \ac{iq} sample per clock cycle: the 16-bit Q component
        in bits~[31:16] and the 16-bit I component in bits~[15:0],
        both signed two's complement~\cite{AMD_PG269}.
  \item The \ac{cdc} \ac{fifo} bridges the 250\,MHz
        \ac{pl} fabric domain of PL-09 to the
        \texttt{s0\_axis\_aclk} domain of the \ac{rfdc}.
        The \ac{fifo} must use \texttt{clk\_dac0} (40.204\,MHz)
        as its read-side master clock to maintain synchrony with
        the \ac{rfdac} tile fabric interface~\cite{AMD_PG269}.
  \item No \texttt{tlast} signal is used on this path.
        The \ac{iq} stream is continuous during active transmission.
  \item Idle gaps in the stream are permissible.
        \texttt{s00\_axis\_tready} de-asserts when the internal
        \ac{rfdac} \ac{fifo} is full.
        The upstream \ac{cdc} \ac{fifo} must absorb the resulting
        backpressure~\cite{AMD_PG269}.
  \item The upstream source must hold \texttt{tdata} and
        \texttt{tvalid} stable while
        \texttt{s00\_axis\_tready} is
        deasserted~\cite{ARM_IHI0022}.
\end{tightemize}

\textit{Downstream} (\texttt{vout00}, to RF-01 balun and SMA
connector):
\begin{tightemize}
  \item The \texttt{vout00} differential port drives the MACOM
        MABA-011118 balun mounted on the \ac{rfsoc}~4x2
        board~\cite{RealDigital_A6}.
        The signal chain between the \ac{rfdac} output and the
        SMA connector is entirely passive: decoupling capacitors
        and the balun only, with no active components between
        the \ac{rfdac} and the \ac{rf} output~\cite{RealDigital_A6}.
  \item The effective \ac{rf} center frequency of the transmitted
        signal is 177\,MHz, determined by the fine \ac{nco}
        with the coarse mixer bypassed at runtime~\cite{AMD_PG269}.
  \item No digital backpressure mechanism exists downstream of
        the \ac{dac}.
        The analog output is unconditional once the \ac{rfdc} is
        configured and data flow is active~\cite{AMD_PG269}.
\end{tightemize}

\section{RF TX Front-End}
\label{sec:rf_frontend}

The \ac{rf} transmit front-end converts the differential analog
output of the \ac{rfdc} \ac{dac} tile to a single-ended 50\,$\Omega$
signal on a board-accessible \ac{sma} connector for delivery to
external test equipment or a cable receiver.
The front-end consists entirely of passive board-level components
and consumes no \ac{fpga} resources~\cite{RealDigital_A6}.

\section{Clocking Subsystem}
\label{sec:clocking}

The \ac{rfdc} \ac{dac} and \ac{adc} tiles require a stable 321.632\,MHz
reference clock for internal sample-rate \ac{PLL} lock~\cite{AMD_PG269}.
This reference is produced by a two-stage chain: a TI LMK04828 jitter
cleaner~\cite{TI_LMK04828} conditions the board crystal reference to
245.76\,MHz, and a pair of TI LMX2594 \ac{rf} synthesizers~\cite{TI_LMX2594}
multiply that signal to 321.632\,MHz.

% ------------------------------------------------------------
\subsection{LMK04828}
\label{subsec:lmk04828}

The LMK04828 is a dual-loop \ac{PLL} clock jitter cleaner mounted on the
\ac{rfsoc}~4x2 board~\cite{RealDigital_A6}.
It accepts a 10\,MHz low-voltage differential signaling (LVDS) 
reference from the board's Si5395B crystal
oscillator and delivers a 245.76\,MHz differential clock on \texttt{OUT0}
to the \ac{adc} synthesizer and on \texttt{OUT4} to the \ac{dac}
synthesizer~\cite{TI_LMK04828}.
The ANSpect design uses the Xilinx/RealDigital default
\texttt{LMK04828\_245.76.txt} \ac{tics} register file without modification.

% ------------------------------------------------------------
\subsection{LMX2594}
\label{subsec:lmx2594}

Two LMX2594 wideband \ac{rf} synthesizers generate the 321.632\,MHz
reference~\cite{TI_LMX2594}: PLL2 (DAC) feeds \ac{rfdc}-01 DAC\_B
Tile~228 and PLL1 (ADC) feeds \ac{rfdc}-02 ADC\_D Tile~224.
Both devices share the same custom \ac{tics} configuration
(\texttt{LMX2594\_321.632.txt}), generated with \ac{tics} Pro targeting
a 321.632\,MHz output from the 245.76\,MHz LMK04828 reference;
the output frequency follows from \ac{PLL} multiplication to
$F_\text{vco} = 7{,}719.168$\,MHz and a channel divider
$\text{CHDIV} = 24$, giving
$F_\text{out} = 7{,}719.168 / 24 = 321.632$\,MHz~\cite{TI_LMX2594}.

% ------------------------------------------------------------
\subsection{\texttt{xrfclk} API}
\label{subsec:xrfclk}

\texttt{xrfclk} is the \ac{pynq} Python package that programs the
LMK04828 and both LMX2594 devices over the \ac{ps} \ac{spi} bus at
boot~\cite{xrfclk}.
The ANSpect initialization sequence is:

\begin{verbatim}
xrfclk.set_ref_clks(lmk_freq=245.76, lmx_freq=321.632)
time.sleep(2.0)
ol = Overlay("xyz.bit")
\end{verbatim}

The 2\,s sleep provides \ac{PLL} lock acquisition margin; loading the
\ac{pl} bitstream before the sleep elapses prevents the \ac{rfdc} tiles
from acquiring lock and must be avoided~\cite{xrfclk}.

\paragraph{Verification.}

Clock chain lock was confirmed at two levels.
At the hardware level, the \ac{rfsoc}~4x2 board provides four dedicated
lock-status \acp{led}: \texttt{STAT1} and \texttt{STAT2} indicate LMK04828
\ac{PLL}1 and \ac{PLL}2 lock, and the DAC and ADC \acp{led} indicate
LMX2594 PLL2 and PLL1 lock respectively~\cite{RealDigital_A6}.
All four assert green on completion of \texttt{set\_ref\_clks()},
confirming that the full two-stage clock chain is locked before
\texttt{Overlay()} is called.
At the system level, correct clock operation was confirmed by the \ac{rfdc}
passthrough isolation test described in Section~\ref{subsec:dac_tile228},
in which the HDHomeRun consumer receiver reported \texttt{lock=qam256}
at 177MHz center frequency.

\subsection{HDHomeRun: Consumer Lock Validation}
\label{subsec:hdhomerun}

The SiliconDust HDHomeRun Flex Duo (HDFX-2US) is a network-connected
dual-tuner receiver that supports unencrypted QAM-64 and QAM-256
cable signals and reports tuner lock status and signal quality metrics
over a 100BASE-TX Ethernet interface~\cite{HDHomeRun}.
In this work it serves as the consumer lock validation instrument:
its reported lock state is the primary pass or fail criterion for
the full-system validation and \ac{rfdc} isolation
tests~\cite{HDHomeRun}.
Results are reported in Sections~\ref{subsec:system_validation}
and~\ref{subsec:lock_failure}.

\subsection{Integration Simulation}
\label{subsec:integration_sim}

Integration simulation was conducted in three incremental stages,
each extending the verified chain boundary: PL-02 through PL-04,
PL-02 through PL-06, and PL-02 through PL-08.
Each stage applied golden vector comparison and chain-level
profiling to characterize backpressure propagation, stall duty
cycles, and inter-module timing at each new boundary.
PL-09 (\ac{srrc} pulse shaping) was excluded from integration
simulation: the Xilinx \texttt{FIR Compiler} behavioral model
required 30--40 minutes per simulation test case on the development
system and crashed before completing a full run.
PL-09 is validated in hardware only
(Section~\ref{subsec:txchain_board}).

\FloatBarrier
\paragraph{Clock Frequency Selection.}
\leavevmode\par

The \ac{rfsoc}~4x2 \ac{pl} base clock is 100\,MHz at the
hardware level.
The 250\,MHz production clock is derived from this
base, and all \ac{ps}-to-\ac{pl} \ac{axi} interfaces operate
at the 100\,MHz base clock, introducing a clock-domain crossing
at the \ac{pl} boundary.
Stage~2 profiling was run at both 100\,MHz and 250\,MHz to
determine whether the base clock could sustain the target output
rate and avoid this crossing~\cite{ITU_J83,DOCSIS3}.
The logic was confirmed clock-rate agnostic: all cycle counts,
state transitions, and golden vector outputs were identical at
both frequencies, with the only difference being wall-clock
execution time.
At 100\,MHz, the chain produces approximately 14.3\,Msym/s.
While this exceeds the single-channel requirement of
5.360537\,Msym/s~\cite{ITU_J83}, it leaves insufficient headroom
for downstream modules not yet integrated at Stage~2 and
eliminates margin for future multi-channel operation.
At 250\,MHz, the full Stage~3 chain measured 29.3\,Msym/s, a
5.5$\times$ margin over the single-channel requirement.
250\,MHz was selected as the production \ac{pl} clock on this
basis.

\FloatBarrier

\leavevmode\par

The dominant chain characteristic is PL-06's 1/7 output duty
cycle: each 7-bit symbol is serialized one bit per clock cycle,
reducing the effective output rate to one-seventh of the fabric
clock and propagating backpressure upstream through every preceding
module.

contribution of each module as observed across all three integration
stages.

input (41,520/41,520 golden matches, all 141 tests).

\subsection{TX-Chain Board Validation}
\label{subsec:txchain_board}

Each integration boundary (PL-02 through PL-04, PL-06, and PL-08)
was verified on hardware via \ac{dma} loopback golden vector
comparison against 250 \ac{mpegts} packets at 250\,MHz; all
boundaries passed.
PL-09 (\ac{srrc} pulse shaping) was verified in isolation using
the PL-08 golden output as \ac{dma} input and passed golden vector
comparison on hardware, constituting its sole verification
(Section~\ref{subsec:integration_sim}).

\paragraph{Full-Chain Stream Continuity.}
\leavevmode\par

The PL-02 through PL-09 chain including the \ac{cdc}~\ac{fifo} was exercised via PL-01 (\ac{axi}
DMA MM2S) in Scatter-Gather cyclic mode, driven by PS-03, feeding
276,349 \ac{mpegts} packets continuously across 14 cyclic passes.
A custom \ac{axi}-Stream monitoring module inserted at the
clock-domain crossing \ac{fifo} output measured total clock cycles
and total valid output samples from first valid output to the end
of the measurement window.

\subsection{RFDC Isolation Test}
\label{subsec:rfdc_isolation}

The \ac{rfdc} isolation test validated the \ac{dac} and \ac{adc}
subsystem configuration against ANSpect requirements:
\texttt{DAC\_B} at $+$177.0\,MHz \ac{nco}, 40$\times$
interpolation, 32.163\,Msps baseband input rate (first Nyquist
zone); \texttt{ADC\_D} at $-$177.0\,MHz \ac{nco}, 40$\times$
decimation, 32.163\,Msps output rate.
The test exercised the complete \ac{rfdc} signal path, including
the asynchronous clock-domain crossing between the \ac{adc} and
\ac{dac} clock domains, without involvement of the digital
transmit chain.

\FloatBarrier
\paragraph{Test Configuration.}
\leavevmode\par

A passthrough bitstream routed the \texttt{ADC\_D} output to
\texttt{DAC\_B} through an asynchronous clock-domain crossing
\ac{fifo}, with the \ac{adc} clock domain driving the \ac{fifo}
write port and the \ac{dac} clock domain driving the read port.
The Thor H-Thunder-1 signal generator provided a J.83B 256-QAM
reference at 177.0\,MHz (cable Ch.\,7) through a
75\,$\Omega$-to-50\,$\Omega$ impedance matching pad to
\texttt{ADC\_D}.
The \texttt{DAC\_B} output was routed through a
50\,$\Omega$-to-75\,$\Omega$ matching pad to the HDHomeRun
consumer demodulator, tuned to 256-QAM at 177.0\,MHz.
Full \ac{rfdc} parameter configuration is given in
Section~\ref{sec:rfdc}. % label: match §4.4 RFDC label

The HDHomeRun demodulator acquired full lock on the passthrough

\subsection{Full System Validation}
\label{subsec:system_validation}

The full system validation exercised the complete transmit path from
the \ac{ps} software layer through the digital \ac{pl} chain, the
\ac{rfdc} \ac{dac}, and the \ac{rf} output to the cable plant.
The \ac{ps} supplied pre-computed \ac{mpegts} test vectors to
PL-01 in Scatter-Gather cyclic mode; the PL-02 through PL-09 chain
processed the stream continuously; and the \ac{rfdc} \ac{dac}
upconverted the baseband output to 177.0\,MHz (DOCSIS cable
channel~7).
Spectrum measurements were acquired at the \ac{rf} output using the
Anritsu MS2721B spectrum analyzer in RMS/Average detection mode
(10-trace average, RBW\,=\,100\,kHz, VBW\,=\,10\,kHz).

\FloatBarrier
\paragraph{Spectral Measurements.}
\leavevmode\par

The measured channel power at 177.0\,MHz over a 6.000\,MHz integration
bandwidth was $-$28.6\,dBm.
The 99\,\% occupied bandwidth was 5.526\,MHz, contained within the
6.000\,MHz DOCSIS channel allocation.
The spectral shape exhibits a flat passband with steep roll-off edges
consistent with the \ac{srrc} pulse-shaping filter implemented in
PL-09 (Section~\ref{subsec:srrc_tx}).
Figures~\ref{fig:anritsu_ch_power} and~\ref{fig:anritsu_occ_bw} show
the channel-power and occupied-bandwidth captures, respectively.
